# Quick start

This gets you from a fresh checkout to playing in the browser.

## Prerequisites

| Tool | Used for | Required? |
| --- | --- | --- |
| [Unity 6](https://unity.com/download) (6000.0 LTS) with the **WebGL Build Support** module | Building the client in the editor | Only if not building in Docker |
| A Unity license (the free Personal one works) | Building the client, in Docker or the editor | Yes |
| [Docker](https://docs.docker.com/get-docker/) with Compose | Running the server | Yes (or Node.js 18+) |
| [Task](https://taskfile.dev/installation/) | Shortcut commands | Recommended |
| [.NET SDK 8](https://dotnet.microsoft.com/download) | Compiling the C# without Unity (`task client:check`) | Optional |

!!! tip "Other Unity versions"
    The code works with Unity 2022.3 LTS and newer. When Unity Hub asks to change the editor version, accept it.

## 1. Build the browser client

=== "Docker (no Unity install)"

    Unity needs a license even in Docker; the free Personal license works. Get one in your browser (once), then build:

    ```bash
    task license:activate   # opens Unity Hub in your browser; saves unity-license/Unity_lic.ulf
    task client:build
    ```

    See [Building the client in Docker](../deployment/docker-client-build.md) for details and other license options.

=== "Unity editor"

    1. In Unity Hub choose **Add → Add project from disk** and select the `Shadowfall` folder.
    2. Open the project. The first import takes a few minutes.
    3. From the menu bar choose **Shadowfall → Build WebGL (into server folder)**.

=== "Local Unity, headless"

    ```bash
    export UNITY_PATH="/path/to/Unity"   # see Taskfile.yml for per-OS examples
    task client:build:local
    ```

Every option writes the build to `server/public/`. The first build takes a while; later builds are faster.

## 2. Start the server

=== "Task"

    ```bash
    task up
    ```

=== "Docker Compose"

    ```bash
    cd server
    docker compose up -d --build
    ```

=== "Node.js (no Docker)"

    ```bash
    cd server
    npm ci
    npm start
    ```

Open **<http://localhost:7341>** in your browser.

## 3. Play

1. Click **Create an account**: choose an account name and a password (an email address is optional, for password resets). Write down the **recovery code** you are shown: it lets you reset a forgotten password.
2. Create your first hero: a name and a class, **Knight**, **Barbarian**, **Mage** or **Rogue**. Other players see your choice, and the class can't be changed later. One account holds up to 10 heroes; ++esc++ → **Character Select** switches between them.
3. Talk to **Captain Aldric** (yellow `!`) by Hollowmere's north gate to get your first quest.
4. Press ++f1++ in game to see the controls.

!!! note "The first login uploads the world map"
    Monsters are simulated by the server, so the server needs to know where the walls, trees and water are. The world is generated by the client from a fixed seed, so the **first** client to enter the world uploads its walkability map. The server stores it in `data/world.json`. See [Architecture → World map](../architecture/overview.md#world-map).

!!! note "Where accounts are stored"
    With Docker, accounts and characters are kept in a PostgreSQL container that `task up` starts next to the game. With `npm start` or `task server:dev` they are JSON files in `server/data`. Characters from older versions are imported automatically: log in with the character's name and old password. See [Accounts & passwords](../deployment/accounts.md).

## Playing from the Unity editor

You can also press **Play** in the editor while the server runs locally. On the login screen, the **Server** field defaults to `ws://localhost:7341/ws`. Browser builds always connect back to the server that served the page.

Invite friends by sending them your server's address. Everyone shares the same world.

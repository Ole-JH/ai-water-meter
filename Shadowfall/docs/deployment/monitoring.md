# Monitoring

`task up` (and so `task update`) starts a full monitoring stack next to the game server:

| Service | What it does | Where |
| --- | --- | --- |
| **Grafana** | Dashboards, log search, alert overview | <http://localhost:3000> (`GRAFANA_PORT`) |
| **Prometheus** | Collects and stores metrics (30 days) and evaluates the alert rules | <http://localhost:9090>, this machine only |
| **Alertmanager** | Groups alerts and sends notifications (none until you configure a receiver) | <http://localhost:9093>, this machine only |
| **Loki** + **Grafana Alloy** | Collects every container's log lines (14 days) | through Grafana |
| **node-exporter** | Host metrics: CPU, memory, disks, network | through Grafana |
| **cAdvisor** | Per-container CPU, memory, network and disk | through Grafana |
| **postgres-exporter** | The account database: up, size, connections, transactions | through Grafana |

Only the game port and Grafana are published to the network. The game server's metrics are on a private port (`9464`) that
only the other containers can reach, never on the public game port.

## First login

Open <http://localhost:3000> and log in as `admin` / `admin`; Grafana asks you to choose a new password. To set it up front,
put it in `server/.env` (which is not committed):

```bash
GRAFANA_ADMIN_PASSWORD=something-long
```

If Grafana is reachable from the internet, also put it behind the [reverse proxy](reverse-proxy.md) with HTTPS, or bind it to
this machine only with `GRAFANA_BIND=127.0.0.1` and use an SSH tunnel.

## Dashboards

Three dashboards are provisioned in the **Shadowfall** folder; the first is Grafana's home page.

**Shadowfall** (generated by `tools/monitoring/shadowfall_dashboard.py`):

- **Overview**: server up, players online, players in dungeons, monsters alive, accounts, uptime.
- **Players**: online, in dungeons, connections and parties over time; players by class and by level band; logins per hour
  (`ok`, `new` accounts, `bad_password`, `locked`).
- **Accounts**: accounts and characters over time, failed and blocked logins per 10 minutes, password resets per hour by method.
- **World & combat**: monsters and elites alive, kills per minute by monster, most killed monsters and bosses slain in the
  selected time range, player deaths, open dungeon instances, dungeon runs by dungeon and difficulty.
- **Economy & social**: trades, chat messages, admin commands.
- **Server health**: simulation tick time (p50/p95/p99), event loop lag, errors, memory, CPU, network, messages per second.
- **Database**: PostgreSQL up, database size, connections, transactions per second (commits, rollbacks), rows inserted,
  updated and deleted per second (from postgres-exporter).
- **Logs**: the game server's log, with a search box at the top. Server restarts are marked on every graph.

**Node Exporter Full** ([grafana.com 1860](https://grafana.com/grafana/dashboards/1860)): everything about the host.

**cAdvisor** ([grafana.com 19792](https://grafana.com/grafana/dashboards/19792)): every container's resource use.

Dashboards are editable in Grafana, but the files in `server/monitoring/grafana/dashboards` win on the next start. To change the
Shadowfall dashboard for good, edit the generator and run `task monitoring:dashboard`.

## Metrics

The game server exports these (all prefixed `shadowfall_`):

| Metric | Type | Labels |
| --- | --- | --- |
| `players_online`, `players_in_dungeons`, `connections`, `parties`, `trades_open`, `accounts`, `characters`, `elites_alive`, `world_loaded` | gauge | |
| `storage_info` | gauge (always 1) | `kind` (postgres, files) |
| `players_by_class`, `players_by_level` | gauge | `class`, `band` |
| `monsters_alive` | gauge | `zone` (overworld, dungeon) |
| `dungeon_instances` | gauge | `dungeon` |
| `logins_total` | counter | `result` (ok, new = account created, bad_password, locked = refused by the [rate limits](accounts.md#rate-limits)) |
| `password_resets_total` | counter | `method` (recovery = recovery code used, code = email or admin code used, admin = code issued with `/a resetpw`, change = changed in game) |
| `monsters_killed_total` | counter | `monster`, `elite` |
| `bosses_killed_total` | counter | `boss` |
| `player_deaths_total`, `trades_completed_total` | counter | |
| `dungeon_entries_total` | counter | `dungeon`, `difficulty` |
| `admin_commands_total` | counter | `cmd` |
| `messages_received_total` | counter | `type` (protocol message type) |
| `messages_sent_total`, `sent_bytes_total`, `received_bytes_total` | counter | |
| `handler_errors_total` | counter | `type` |
| `character_saves_total` | counter | `result` (ok, error) |
| `tick_duration_seconds` | histogram | |

Plus `process_resident_memory_bytes`, `process_cpu_seconds_total`, `process_start_time_seconds`, `nodejs_heap_*` and
`nodejs_eventloop_lag_p99_seconds`. See them live with `task metrics`.

The metrics endpoint is off unless `METRICS_PORT` is set (Docker Compose sets it to `9464`). When running the server with
`task server:dev`, use `METRICS_PORT=9464 task server:dev` and open <http://localhost:9464/metrics>.

To add a metric, define it next to the others in `server.js` (`M.*` for counters and histograms, `metrics.gauge(...)` for values
read at scrape time), then add a panel in the dashboard generator.

## Alerts

`server/monitoring/prometheus/alerts.yml` defines:

| Alert | When |
| --- | --- |
| `ShadowfallDown` | Prometheus can't reach the game server for 2 minutes |
| `ShadowfallSlowTick` | 95% of world ticks take more than 50 ms for 5 minutes |
| `ShadowfallEventLoopLag` | The event loop is blocked for more than 100 ms (p99) for 5 minutes |
| `ShadowfallHandlerErrors` | A client message caused an exception in the last 10 minutes |
| `ShadowfallSaveErrors` | A character could not be saved (is the database down?) |
| `ShadowfallLoginAttack` | More than 100 wrong passwords or locked-out attempts in 15 minutes (someone may be guessing passwords; see the [account events](accounts.md#sql)) |
| `ShadowfallHighMemory` | The game server uses more than 1.5 GB for 10 minutes |
| `PostgresDown` | The account database (or its exporter) is unreachable for 2 minutes: players can't log in or save |
| `PostgresTooManyConnections` | The database uses more than 80% of its connections for 10 minutes |
| `HostDiskAlmostFull`, `HostHighCpu`, `HostLowMemory` | The machine is running out of disk, CPU or memory |

Firing alerts show up in Grafana under **Alerting** and in Prometheus. To be notified, add a receiver (Discord, Slack, email,
any webhook) to `server/monitoring/alertmanager/alertmanager.yml`; the file has an example. Then run `task monitoring:reload`.

## Settings

Set these in `server/.env` or the environment:

| Variable | Default | Meaning |
| --- | --- | --- |
| `GRAFANA_PORT` | `3000` | Host port for Grafana |
| `GRAFANA_BIND` | `0.0.0.0` | Interface Grafana listens on (`127.0.0.1` = this machine only) |
| `GRAFANA_ADMIN_USER` / `GRAFANA_ADMIN_PASSWORD` | `admin` / `admin` | Grafana's first admin account |
| `PROMETHEUS_PORT` / `ALERTMANAGER_PORT` | `9090` / `9093` | Host ports, bound to `127.0.0.1` |
| `PROMETHEUS_RETENTION` | `30d` | How long metrics are kept |

## Running without it

`docker compose up -d shadowfall` (in `server/`) starts only the game and its database. `task monitoring:down` stops the stack; its data is kept in
the `shadowfall-prometheus-data`, `shadowfall-grafana-data`, `shadowfall-loki-data` and `shadowfall-alertmanager-data` volumes.

node-exporter and cAdvisor read the host's `/proc`, `/sys` and Docker directories and cAdvisor runs privileged; Alloy reads the
Docker socket to collect logs. They work on Linux hosts. On Docker Desktop (macOS, Windows) the host panels show the Docker VM
instead of your computer.

## Troubleshooting

- **A panel says "No data"**: counters only appear after the first event (e.g. the first boss kill). Check
  **Status → Targets** in Prometheus (<http://localhost:9090/targets>): every job should be `UP`.
- **`shadowfall` target is down**: the game server isn't running or is older than the metrics support. Run `task up`.
- **`postgres` target is down** or `PostgresDown` fires: `docker compose logs postgres postgres-exporter` (in `server/`). If the
  log says *password authentication failed*, `POSTGRES_PASSWORD` was changed after the database was created; see
  [Accounts → Database password](accounts.md#password).
- **No logs**: `docker compose logs alloy` (in `server/`). Alloy needs read access to `/var/run/docker.sock`.
- **Forgot the Grafana password**:
  `docker compose exec grafana grafana cli admin reset-admin-password <new>`.
